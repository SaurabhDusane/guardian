# Guardian benchmark results

Generated by `bench/run_bench.py --rows 100000 --reps 5`. Each configuration was run
5 times in a fresh storage root, interleaved across repetitions, after one untimed
warm-up. Medians are reported with the min - max range; ± is half the range as a
percentage of the median.

## 1. Throughput during an outage

Rows ingested by b1 per second of end-to-end pipeline wall time (100,000
generated rows of messy demo data, of which b1-b4 quarantine 12.5%
as usual). In the outage run b6 raises on every run; Guardian rolls it back and b8
reads this run's b5 output through `b5_to_b6_shape`
(87,517 rows reach b8 in both configurations).

| Configuration | Median | Min - max (± half-range) | Unit |
|---|---:|---|---|
| Clean run | **22,358** | 22,150 - 22,620 (±1.1%) | rows/s |
| b6 crashed, b8 rerouted to b5 | **23,362** | 22,322 - 23,648 (±2.8%) | rows/s |

Throughput during the outage is **104%** of the clean run, with
the same number of rows reaching b8. (In the outage configuration b6 crashes before doing
any work, so it neither validates nor snapshots its output.)

## 2. Recovery time

Setup (untimed): a clean run r0, then run r1 with 50% of b6's rows corrupted, so b6 is
rolled back and all 87,517 of its r1 rows are quarantined. Timed:
`replay b6_enrich` until it returns, after which b6 is verified to be HEALTHY with the
replay snapshot promoted as last-good (87,517 rows, unique
`order_id`s, upserted into r0's snapshot).

| Configuration | Median | Min - max (± half-range) | Unit |
|---|---:|---|---|
| replay b6_enrich (in-process API) | **2.55** | 2.47 - 2.60 (±2.5%) | s |
| guardian replay b6_enrich (CLI, incl. interpreter start) | **3.72** | 3.68 - 4.36 (±9.1%) | s |

The CLI figure includes starting Python and importing pandas, Pandera, pyarrow and duckdb
(the difference between the two rows).

## 3. Logging overhead

Same blocks, same 100,000 rows of *clean* demo data (`error_rate=0`), because the bare
blocks cannot survive the messy rows Guardian would normally quarantine (b5 fails to cast
NaN quantities to integers). The bare run calls the block functions in topological order
with no validation, snapshots, quarantine, or events.

| Configuration | Median | Min - max (± half-range) | Unit |
|---|---:|---|---|
| Bare run (no Guardian) | **2.67** | 2.62 - 2.74 (±2.3%) | s |
| Guardian, sample rate 1.0 | **3.41** | 3.37 - 3.45 (±1.2%) | s |
| Guardian, sample rate 0.1 | **3.41** | 3.34 - 3.49 (±2.1%) | s |

- Guardian's total overhead over the bare run: **+28%** at sample
  rate 1.0 and **+28%** at 0.1. This is Pandera validation, Parquet
  snapshots, status/last-good bookkeeping and event logging together.
- The event-logging share (median at 1.0 minus median at 0.1) is
  **+1 ms per run (+0.0% of the bare
  run)**, smaller than the run-to-run spread of the Guardian runs (±73 ms).
  A run keeps 36 events at 1.0 and 3 at 0.1: events are
  emitted per block and per decision, not per row.
